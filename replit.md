# StockSmart — Digital Inventory Keeper

A digital inventory management app for small local shops and businesses that currently manage stock manually in notebooks or mentally.

## Run & Operate

- `pnpm --filter @workspace/api-server run dev` — run the API server (port 8080)
- `pnpm --filter @workspace/inventory-app run dev` — run the frontend (port 24449)
- `pnpm run typecheck` — full typecheck across all packages
- `pnpm run build` — typecheck + build all packages
- `pnpm --filter @workspace/api-spec run codegen` — regenerate API hooks and Zod schemas from the OpenAPI spec
- `pnpm --filter @workspace/db run push` — push DB schema changes (dev only)
- Required env: `DATABASE_URL` — Postgres connection string (auto-set by Replit DB)

## Stack

- pnpm workspaces, Node.js 24, TypeScript 5.9
- Frontend: React + Vite, Tailwind CSS, shadcn/ui, wouter (routing), TanStack Query
- API: Express 5
- DB: PostgreSQL + Drizzle ORM
- Validation: Zod (`zod/v4`), `drizzle-zod`
- API codegen: Orval (from OpenAPI spec)
- Build: esbuild (CJS bundle)

## Where things live

- `lib/api-spec/openapi.yaml` — OpenAPI contract (source of truth)
- `lib/db/src/schema/` — Drizzle DB schema (products.ts, movements.ts)
- `artifacts/api-server/src/routes/` — Express route handlers
- `artifacts/inventory-app/src/` — React frontend
- `lib/api-client-react/src/generated/` — auto-generated React Query hooks
- `lib/api-zod/src/generated/` — auto-generated Zod validators

## Architecture decisions

- Contract-first API: OpenAPI spec drives both Zod validation and React Query hooks via Orval codegen
- Numeric quantities stored as `numeric` in Postgres, converted to `Number` in routes before JSON serialization
- Request body schema names use `Input` suffix (e.g. `CreateProductInput`) to avoid name collisions with Orval's generated `Body` schemas
- Stock adjustments recorded in `movements` table with before/after quantities for full audit trail
- `api-zod/src/index.ts` exports only from `./generated/api` (not `./generated/types`) to avoid duplicate export conflicts from Orval

## Product

- **Dashboard**: Total products, low stock count, out of stock count, categories, recent movements, top items running low
- **Products**: Full catalog with search, category filter, low-stock filter; add, edit, delete
- **Stock Adjustment**: Log stock in/out/adjustment with notes per product
- **Movement History**: Full audit trail of all stock changes, filterable by type

## Gotchas

- After `openapi.yaml` changes, always run `pnpm --filter @workspace/api-spec run codegen` before touching frontend or backend
- `api-zod/src/index.ts` is NOT regenerated by codegen (only the generated/ subdirectory is). Safe to edit manually.
- Body schema names in openapi.yaml must use `Input` suffix (not `Body`) to avoid Orval naming conflicts with generated Zod validators
- API server must be restarted after route changes (`restart_workflow "artifacts/api-server: API Server"`)
